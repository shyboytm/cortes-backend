# Code style

Do not add code comments (JS/TS `//` or `/* */`) anywhere in this repo, including explanatory comments on complex logic or Sanity schema definitions, unless the user explicitly asks for a comment in that specific instance. Write self-explanatory code (clear naming, small functions) instead of leaning on comments. Note: Sanity schema `title`/`description` field properties are user-facing Studio UI text, not code comments — those should stay as needed.
